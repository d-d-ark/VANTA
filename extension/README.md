# VANTA Live

현재 개발 버전: **1.1.25**. 확장 프로그램 코드, 스타일 또는 manifest를 변경하는 개발 배치마다 버전을 올립니다. 버전은 서버 호환성 검사에만 사용하며 VANTA 패널에는 표시하지 않습니다.

## 1.1.25 핵심 변경
- 엔트리 도움말 버튼의 드롭다운 장식이 VANTA 버튼에 함께 복제되던 문제를 제거했습니다.
- VANTA 전용 원형 버튼 스타일과 흰색 `V_2.svg`만 사용합니다.

## 1.1.24 핵심 변경
- 패널 로고는 다시 로고만 남기는 접기 기능으로 동작하고, 엔트리 헤더 V 버튼만 패널 전체를 숨깁니다.
- 헤더 아이콘에서 엔트리 아이콘 폰트 클래스를 제거하고 흰색 `V_2.svg`만 표시합니다.

## 1.1.23 핵심 변경
- 엔트리 헤더의 VANTA 버튼을 Live 중에도 계속 표시합니다.
- Live 중 헤더 VANTA 버튼으로 상단 패널을 접고 다시 펼칠 수 있습니다.

## 1.1.22 핵심 변경
- 헤더 VANTA 버튼에 `V_2.svg`를 사용하고 웹 접근 가능 리소스로 등록해 깨진 이미지를 수정했습니다.
- 패널이 열리는 중인 패딩값이 아니라 최종 패딩값으로 너비를 계산해 오른쪽 버튼이 잘리지 않게 했습니다.

## 1.1.21 핵심 변경
- Live가 아닐 때 VANTA 패널을 숨기고 엔트리 헤더에 같은 크기의 VANTA 실행 버튼을 표시합니다.
- 실행 버튼이나 패널 로고를 누르면 패널 너비가 0에서 자연스럽게 열리고 다시 0으로 닫힙니다.

## 1.1.20 핵심 변경
- 연속된 코드 변경 revision을 실시간 스트림에서 하나도 취소하지 않고 도착 순서대로 전달합니다.
- 접속 직후 첫 revision 누락은 전체 복구 대기 없이 즉시 복구하며, 이후 복구 제한도 5초로 단축했습니다.

## 1.1.19 핵심 변경
- 블록을 드래그하는 동안 상대 화면에 같은 블록의 실시간 이동 미리보기를 표시합니다.
- 블록을 놓으면 기존 작품 조각 동기화가 최종 위치를 확정하므로 상대의 실행 취소 기록과 편집 상태를 오염시키지 않습니다.

## 1.1.18 핵심 변경

- 채팅 최소화 상태에서 가장 최근 메시지 1개만 표시합니다.
- 최초 채팅 위치를 인라인 `left/bottom` 값으로 고정해 항상 왼쪽 아래에서 엽니다.

## 1.1.17 핵심 변경

- 새 채팅이 도착하면 최근 메시지까지 자동으로 스크롤합니다.
- 채팅 상단에 최소화·위치 초기화·닫기 창 제어 버튼을 추가했습니다.
- 채팅 스크롤바를 검정 트랙과 VANTA 보라색 손잡이로 변경했습니다.

## 1.1.16 핵심 변경

- 다른 장면·오브젝트에 있는 코드 보드 포인터도 반투명 상태로 계속 이동하도록 보조 좌표를 추가했습니다.
- 채팅 위치를 실제 크기가 생긴 뒤 복원하고, 이전 위치 데이터는 왼쪽 아래 기본 위치로 초기화합니다.

## 1.1.15 핵심 변경

- 채팅 기록을 Cursor Firebase의 20개 고정 슬롯에 메시지 조각별로 저장합니다.
- 채팅창에서 최근 메시지를 최대 20개까지 확인할 수 있습니다.
- VANTA 777 사용자 관리에 누적 토큰 사용량 정렬을 추가했습니다.

## 1.1.14 핵심 변경

- 모든 엔트리 `/ws`에서 VANTA 패널을 열린 상태로 시작합니다.
- 새 설치에서 처음 한 번만 환영·패널·Live·설정을 안내하는 단계형 튜토리얼을 표시합니다.
- VANTA 777에 협업 코드 삭제와 사용자 검색 실행 버튼을 추가했습니다.

## 1.1.13 핵심 변경

- 자동 생성 CSS 클래스의 마지막 텍스트를 닉네임으로 추측하던 방식을 제거했습니다.
- 엔트리의 `__NEXT_DATA__.props.pageProps.initialState.common.user.nickname`만 사용하며 로그아웃 상태는 `익명`으로 표시합니다.

## 1.1.12 핵심 변경

- 설정을 연 상태에서 서버가 새로 반환한 토큰 초기화 보유량이 즉시 표시됩니다.
- snake_case와 camelCase 할당량 응답을 모두 읽어 이전 응답 형태에도 안전하게 대응합니다.

## 1.1.11 핵심 변경
- 실시간 스트림 재접속은 서버의 `Retry-After`를 따르며 1초부터 최대 30초까지 단계적으로 대기합니다.
- 스트림 장애 중 전체 작품 복구 다운로드는 최대 30초에 한 번으로 제한합니다.
- 통신 규격은 release 54를 유지해 1.1.10과 같은 Live에서 함께 사용할 수 있습니다.

## 1.1.10 핵심 변경

- Live 커서 Firebase 연결을 서비스 워커로 옮기고 `offscreen` 권한을 제거했습니다.
- 커서 스트림이 일시적으로 끊기면 서비스 워커에서 자동으로 다시 연결합니다.

## 1.1.9 핵심 변경

- 개발용 `좌표 구역 보기` 항목을 사용자 설정에서 숨겼습니다.

## 1.1.8 핵심 변경

- 코드 보드 이동과 확대는 작품 수정으로 전송하지 않고 각 사용자에게만 유지합니다.
- 실제 원격 변경을 적용해도 현재 오브젝트의 코드 보드 위치와 확대 배율을 복원합니다.
- 내보내는 코드 배치는 공통 원점으로 정규화해, 시점 이동 때문에 작품 조각 전체가 다시 전송되는 현상을 막습니다.

## 1.1.7 핵심 변경
- 코드 보드의 빈 공간도 화면 비율이 아닌 가장 가까운 공통 블록을 기준점으로 삼아 위치를 전달합니다.
- 두 사용자가 코드 보드를 서로 다르게 이동하거나 화면 비율이 달라도, 빈 공간 포인터가 같은 작업 위치에 나타납니다.

## 1.1.6 핵심 변경
- 코드 보드에서 블록을 벗어나 빈 공간으로 이동할 때 이전 블록 좌표를 보드 전체 좌표로 잘못 해석해 포인터가 튀던 문제를 수정했습니다.
- 빈 공간으로 전환할 때는 블록을 다시 탐색하지 않고 코드 보드 전체 비율 좌표로만 자연스럽게 이어집니다.

## 1.1.5 핵심 변경
- Cursor Firebase 규칙에 `enginebar` 구역을 추가해 오브젝트 추가·시작 버튼 줄에서도 상대 포인터가 표시되도록 수정했습니다.

## 1.1.4 핵심 변경
- 브라우저마다 새로 생성되어 서로 달랐던 SVG 바깥 ID 대신, 두 화면에서 동일한 엔트리 원본 `blockId`를 코드 보드 포인터 기준으로 사용합니다.
- 같은 블록 안의 포인터 위치를 블록 사각형 내부 비율로 전달하여 화면 크기와 코드 보드 이동 위치가 달라도 같은 지점을 가리킵니다.

## 1.1.3 핵심 변경
- 좌표 구역 보기의 장면 영역을 엔트리 상단 파란색 헤더 전체로 넓히고 표시 이름을 `헤더`로 변경했습니다.
- 코드 보드에 10×10 좌표 격자와 실시간 좌표 탐침을 추가해, 빈 공간은 보드 비율로, 블록 위는 실제 블록 ID와 SVG 좌표로 확인할 수 있습니다.

## 1.1.2 핵심 변경
- 엔트리 워크스페이스를 실제 DOM 구역으로 판정하고, 오브젝트 추가·시작 버튼 줄을 실행 화면과 분리했습니다.
- 코드 보드 포인터는 배열 위치나 가까운 블록 대신 실제 블록 ID와 SVG 좌표 변환을 사용하며, 빈 공간은 코드 보드 비율 좌표를 사용합니다.
- 설정의 `좌표 구역 보기`를 켜면 VANTA가 판정하는 작업 구역을 반투명 색상으로 확인할 수 있습니다.

## 1.1.1 핵심 변경
- Live 시작 전 패널을 펼칠 때 애니메이션 중간 여백을 최종 폭으로 잘못 저장해 공유 버튼이 오른쪽으로 삐져나오던 문제를 수정했습니다.

## 1.1.0 핵심 변경
- 패널 너비와 설정 닫힘 모션, 프로필 표시 개선을 포함한 현재 안정화 버전을 1.1.0으로 배포합니다.

## 1.0.41 핵심 변경
- 설정 창이 닫힐 때 패널 배경은 즉시 부드럽게 줄어들고, 상단 버튼 영역은 축소가 끝날 때까지 오른쪽 정렬을 유지하도록 수정했습니다.

## 1.0.40 핵심 변경
- 패널이 줄어드는 동안 버튼 묶음이 오른쪽 정렬을 유지하도록 수정했습니다.
- 프로필 글자를 정중앙에 굵게 표시하고 방장 프로필 테두리를 더 두껍게 강조했습니다.

## 1.0.39 핵심 변경
- 패널 폭을 상태별 추정값으로 재사용하지 않고, 현재 보이는 로고·문구·버튼·간격을 실시간으로 합산해 정합니다.
- 버튼이나 상태 문구가 바뀌면 자동으로 다시 측정하며, 패널 배경이 내용보다 먼저 목표 폭에 도착하도록 조정했습니다.

## 1.0.38 핵심 변경
- 우측 정렬용 `margin-left: auto`가 화면상 84px 같은 고정 콘텐츠 너비로 다시 합산되던 순환 계산을 제거해, 상태 문구가 사라진 뒤에도 패널에 빈 폭이 남는 문제를 수정했습니다.

## 1.0.37 핵심 변경
- 1.0.34에서 도입한 임시 `width-animating` 정렬을 제거해 펼치기가 86px에서 멈추거나 패널이 불필요하게 387px까지 넓어지는 문제를 근본적으로 수정했습니다.
- 닫힌 설정 행을 포함하던 `width: auto` 측정 대신 현재 보이는 로고·상태·버튼만 합산하고, 버튼은 항상 오른쪽 정렬을 유지해 패널 폭을 따라 자연스럽게 이동합니다.

## 1.0.36 핵심 변경
- 로고, 상태, 버튼과 설정 행의 실제 너비를 합산해 패널의 최종 폭을 정하도록 변경하여 마지막 버튼이 오른쪽 경계에서 잘리는 문제를 수정했습니다.
- 접힌 패널 안에서 버튼 묶음의 화면 너비가 0에 가깝게 측정되더라도 내부 고유 너비와 여백을 사용해 패널이 끝까지 펼쳐지도록 수정했습니다.

## 1.0.35 핵심 변경
- 패널 너비 전환 중 상단 행과 내용 영역을 안전하게 축소·클리핑해 버튼이 패널 배경 밖으로 삐져나오지 않도록 수정했습니다.

## 1.0.34 핵심 변경
- 패널 너비가 줄어드는 동안 상단 버튼을 오른쪽 가장자리에 고정해, 버튼이 순간 이동하지 않고 패널 폭을 따라 부드럽게 이동합니다.

## 1.0.33 핵심 변경
- Live 진입 시 엔트리의 `작품 복구` 창이 나타나면 VANTA가 자동으로 `아니요`를 선택한 뒤 방 작품을 불러옵니다.
- 초기 작품 불러오기에 실패해도 Live 방을 삭제하지 않아 같은 링크에서 다시 연결할 수 있습니다.
- 설정, 상태 문구, 참여자 등 패널 내용이 바뀔 때 전체 패널 너비가 부드럽게 전환됩니다.
- 최대 인원, 토큰, 링크, 익명 모드, Live 커서, 색상 설정 행의 높이를 모두 동일하게 맞췄습니다.

## 1.0.32 핵심 변경
- 같은 탭이 새 Live로 이동할 때 이전 Live 종료 요청과 새 연결 요청이 엇갈려 발생하던 일시적인 중복 Live 오류를 수정했습니다.
- 설정 단축 링크를 연결 완료 후에도 보장하고, 상단 복사 결과와 설정 링크를 함께 갱신하도록 수정했습니다.
- Live 커서와 프로필 색상 행의 겹침을 없애고 설정 패널이 가로로 늘어나는 대신 세로로만 자연스럽게 열리도록 개선했습니다.

## 1.0.31 핵심 변경
- 설정 패널의 실제 높이를 측정해 열기와 닫기 모션이 같은 속도로 자연스럽게 이어지도록 개선했습니다.
- Live 커서의 오래된 토큰 정보가 초기화 직후 표시를 되돌리던 문제를 수정하고 초기화 완료 피드백을 추가했습니다.

## 1.0.30 핵심 변경

- Firebase Console의 다운로드·저장량 측정값을 매 수집마다 서버 이력으로 누적합니다.

## 1.0.28 핵심 변경

## 1.0.22 핵심 변경

- 이전 전체 작품 동기화와 `syncVersion 1` 스트림 경로를 제거하고 조각 동기화만 지원합니다.
- LLNKKR 서버, Sync/Cursor Firebase 규칙과 확장 프로그램은 release 52만 허용합니다.
- 작품 동기화용 Firebase와 커서용 Firebase를 분리했습니다.
- 새 방은 LLNKKR이 지정한 Sync/Cursor 샤드에 고정되며, 운영 중인 방은 중간에 다른 샤드로 이동하지 않습니다.
- 관리자는 VANTA 777에서 새 방에 사용할 `Sync A/B`, `Cursor A/B`를 선택할 수 있습니다.
- 기본 커서는 LLNKKR을 통해 동작하며 최대 초당 5회 전송합니다.
- `Fast 커서`를 켜면 사용자의 명시적 권한 승인 후 Cursor Firebase에 직접 연결하며 최대 초당 10회 전송합니다.
- 커서가 움직이지 않으면 중복 좌표를 보내지 않고, 연결 유지를 위해 1초마다 한 번만 상태를 갱신합니다.
- 커서 샘플에 연결 ID와 순번을 포함해 늦게 도착한 과거 좌표가 최신 위치를 되돌리지 못하게 했습니다.
- Fast 연결이 비활성화되거나 권한·용량·서버 상태 문제로 실패하면 Live를 끊지 않고 기본 커서로 자동 복귀합니다.
- Firebase 직접 연결 권한은 `optional_host_permissions`로 분리했습니다. 확장 프로그램 업데이트만으로 새 권한 경고가 뜨지 않으며, Fast 커서를 처음 켤 때만 권한을 요청합니다.
- 서버 관리자는 전체 사용자에게 Fast 커서를 즉시 허용하거나 차단할 수 있습니다.
- 향후 Firebase B/C 프로젝트를 추가할 때 확장 프로그램을 다시 업데이트하지 않고 서버 설정만으로 새 방의 샤드를 전환할 수 있습니다.

## 작품 동기화

- 작품 전체를 주기적으로 보내지 않고 오브젝트, 장면, 변수, 신호, 함수, 테이블과 메타데이터를 ID 기반 조각으로 나눕니다.
- 변경된 조각만 LLNKKR 검증 API를 거쳐 Firebase에 원자적으로 반영합니다.
- 수신 측은 조각을 메모리에서 전체 작품으로 다시 조립한 뒤 검증된 `Entry.loadProject()` 경로로 적용합니다.
- revision 누락이나 해시 불일치가 있을 때만 현재 작품 전체를 한 번 다시 받아 복구합니다.
- `Entry.do`는 변경 감지 신호로만 사용하며, 원본 명령 이름이나 직렬화할 수 없는 내부 객체를 네트워크로 전송하지 않습니다.
- 서버는 초기 작품, 단일 변경, 조각 개수와 누적 크기에 상한을 두어 큰 작품이나 비정상 요청을 차단합니다.

## 실시간 기능

- 참여자 목록과 최대 인원 2~5명 설정
- 최근 20개 메시지를 유지하는 실시간 채팅
- 익명 모드와 개인 프로필·포인터 색상
- 장면, 오브젝트, 블록 작업 공간을 구분하는 상대 포인터 좌표
- 프로필 클릭 시 상대가 작업 중인 장면 또는 오브젝트로 이동
- 함수 편집과 리스트·속성 탭 등 개인 편집 상태를 최대한 유지한 원격 변경 반영

## 연결 구조

```text
확장 프로그램 ── 작품/채팅 ── LLNKKR ── Sync Firebase
       └──── Live 커서(방 전체 ON/OFF) ───── Cursor Firebase
```

- LLNKKR은 방 생성, 참가자 검증, 토큰 제한, 용량 제한, 버전 정책과 샤드 배정을 담당합니다.
- 확장 프로그램에는 Firebase 서비스 계정 비밀키를 넣지 않습니다.
- Live 커서용 Firebase 토큰은 방·참가자·프로토콜·샤드에 묶인 짧은 수명의 토큰입니다.
- Firebase 규칙은 자신의 커서 슬롯만 쓰도록 제한하며 임의 방이나 다른 참여자의 데이터를 수정하지 못하게 합니다.

## 파일 구조

- `manifest.json`: Manifest V3 권한, 버전, 콘텐츠 스크립트
- `src/content.js`: VANTA 패널, Entry 상태 추출·적용, 커서·채팅 UI
- `src/background.js`: LLNKKR 통신, 실시간 스트림, 방 전체 Live 커서 연결
- `src/page-runtime.js`: Entry 페이지 컨텍스트와 안전한 프로젝트 입출력
- `src/project-chunks.js`: 작품 분할, delta 생성, 병합과 검증
- `styles/vanta.css`: VANTA UI 스타일
- `tests/`: 동기화, 보안, manifest와 UI 정적 테스트

## 테스트

```powershell
node --test tests/*.test.mjs
node --check src/background.js
node --check src/content.js
```

Chrome과 Opera에 같은 개발 폴더를 각각 설치하면 서로 다른 VANTA 참가자로 실제 협업을 검증할 수 있습니다.

## 배포 주의

확장 프로그램, LLNKKR 서버와 Firebase 규칙은 같은 release를 사용해야 합니다. 서버와 규칙을 먼저 새 release로 전환하면 아직 업데이트되지 않은 기존 확장 프로그램이 연결되지 않을 수 있으므로, Chrome 웹 스토어 배포 시점에 맞춰 함께 전환합니다.

VANTA의 소스 코드와 브랜드 자산은 별도 허가 없이 복제, 수정, 재배포 또는 상업적으로 사용할 수 없습니다.
